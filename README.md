# Sorting seminars 1–4 (C++17)

Проект содержит все 12 алгоритмов из семинаров 1–4 и единый тестовый проект на Google Test.

## Состав

- `include/` — заголовочные файлы алгоритмов и общий вспомогательный заголовок внешних сортировок.
- `src/` — отдельный `.cpp` для каждой сортировки.
- `tests/test_all_sorts.cpp` — один параметризованный файл тестов: одинаковые тестовые сценарии запускаются для каждого алгоритма.
- `sorting` — библиотека с реализациями алгоритмов.
- `sorting_tests` — отдельный исполняемый проект с unit-тестами.

### Алгоритмы

**Семинар 1:** `insertion_sort`, `selection_sort`, `exchange_sort`, `bubble_sort`, `optimized_bubble_sort`.

**Семинар 2:** `binary_insertion_sort`, `shaker_sort`.

**Семинар 3:** `shell_sort`, `quick_sort`.

**Семинар 4:** `two_phase_merge_sort`, `one_phase_merge_sort`, `natural_merge_sort`.

Все функции находятся в пространстве имён `sorting`, принимают `std::vector<T>&` и сортируют по возрастанию на месте. Например:

```cpp
#include "insertion_sort.h"
#include <vector>

int main() {
    std::vector<int> values{5, 1, 4, 2, 8};
    sorting::insertion_sort(values);
}
```

Шаблонные реализации находятся в `.h`, потому что компилятору необходимо видеть их определения при инстанцировании шаблонов. В соответствующих `.cpp` явно инстанцированы типы `int` и `double`; эти `.cpp` нужны для сборки библиотеки и согласуются с требованием иметь отдельную пару `.h`/`.cpp` для каждого алгоритма. Для других типов шаблон также доступен из заголовка, если тип поддерживает сравнение и потоковый ввод/вывод (последнее нужно внешним сортировкам).

## Сборка и запуск тестов

Требуется CMake 3.20+ и компилятор с поддержкой C++17. Google Test автоматически загружается через CMake FetchContent, поэтому при первой конфигурации необходим доступ к GitHub.

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

В Visual Studio можно открыть папку проекта через **File → Open → Folder**, либо открыть `CMakeLists.txt` как CMake-проект. Если преподаватель требует именно `.sln`, в Visual Studio можно сгенерировать solution командой CMake для генератора Visual Studio.

## Покрытие тестами

Один набор тестов повторяется для каждого алгоритма. Для целых чисел проверяются пустой вектор, один элемент, уже отсортированный набор, обратный порядок, отрицательные числа и дубликаты, а также перемешанные значения. Дополнительные параметры проверяют работу с `double`. Итого более трёх проверок на каждый алгоритм.

## Реализация внешних сортировок

Внешние сортировки используют временные файлы в системной временной папке. Рабочие файлы удаляются автоматически, в том числе при выходе из функции.

- `two_phase_merge_sort` — чередующееся распределение серий фиксированной длины в два файла, затем слияние обратно в основной файл; длина серии удваивается на каждом проходе.
- `one_phase_merge_sort` — после начального распределения слияние сразу распределяет результаты по следующей паре файлов; отдельное обратное распределение после слияния не требуется.
- `natural_merge_sort` — на каждом проходе выделяются максимальные неубывающие серии, которые затем попарно сливаются.
